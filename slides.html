01 / 用户与问题

四个人讨论，该去哪儿？

学生通常要分别核对场地容量、能否讨论和预约规则。

输入　人数 + 用途；也可单问预约或开放时间。

输出　推荐地点、预约条件、资料编号。

边界　校园场景原型；场地与规则均为模拟数据。

02 / 系统架构

模型选工具，程序查资料

工具只读本地 JSON 和固定 Skill 文件；页面同时显示建议和执行记录。

离线演练沿用同一工具层，用确定规则编排。

03 / 工具与技能

三次调用，各有分工

加载技能　load_skill：取回推荐步骤与输出规则。

筛选地点　search_spaces：按容量和讨论需求筛选。

核对规则　lookup_policy：返回预约或开放规则及 ID。

示例：4 人讨论 → 青禾研讨室 / S01 → 预约规则 / P01。

04 / 关键实现与课程实践

把模型和工具串成闭环

模型接口　OpenAI 兼容 Chat Completions；传入工具参数定义。

调用循环　读取 tool_calls，执行后用调用 ID 回传结果。

相对 demo_5　延续 Agent、Skill、WebUI 的思路，加入场地筛选、来源编号和可展开的调用记录。

05 / 稳定性与合规

没有依据时，明确说没有

缺条件　追问人数和用途；无匹配时建议拆组。

工具边界　限定工具名、参数类型、枚举与人数；最多六轮模型请求。

数据边界　模拟资料、只读、不收集个人信息；密钥仅在服务端配置。

现场备用　接口失败可切离线演练，页面标明规则驱动。
